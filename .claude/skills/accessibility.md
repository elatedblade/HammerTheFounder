# Accessibility (a11y)

Act as an accessibility specialist. Audit and fix my product for
WCAG 2.2 AA compliance.
Deliver:
1. Semantic HTML audit — every page element must use the correct
   HTML5 semantic tag (not div soup).
2. ARIA attributes — where needed, correct roles, labels, live regions.
3. Keyboard navigation — full tab order, focus management, skip links,
   focus trapping in modals.
4. Screen reader testing checklist — what to test with NVDA/VoiceOver.
5. Color contrast — minimum ratios, tool recommendations, dark mode compliance.
6. Form accessibility — labels, error announcements, required field indicators.
7. Image alt text guidelines — when to use, when to mark decorative.
8. Touch targets — minimum 44x44px, spacing requirements.
9. Motion and animation — reduced-motion media query implementation.
10. Automated testing: axe-core, Lighthouse a11y audit integration in CI.
11. Manual testing checklist — keyboard-only, screen reader, zoom 200%.
12. Accessibility statement template for your product.
Failing a11y is not a "nice-to-have fix" — it's a legal liability and
blocks real users. Treat every finding as a P1 bug.
