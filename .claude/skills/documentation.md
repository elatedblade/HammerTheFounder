# Documentation

Act as a technical writer. Create a complete documentation suite for [PRODUCT].
Deliver:
1. README.md — project overview, quickstart, architecture summary.
2. CONTRIBUTING.md — dev setup, code style, PR process, commit conventions.
3. API documentation — auto-generated from OpenAPI spec + hand-written guides.
4. Architecture Decision Records (ADRs) — template + 3 example ADRs
   for key decisions.
5. Runbooks — for common operational tasks (deploy, rollback, DB migration,
   incident response).
6. Onboarding guide — new developer's first-week checklist.
7. User-facing docs — getting started, feature guides, FAQ.
8. Changelog — format, automation strategy (conventional commits).
9. Code documentation — when to write comments (why, not what),
   JSDoc/docstring conventions.
10. Diagram standards — which tool (Mermaid, draw.io), where to store.
Documentation is a product feature. If it's not documented, it doesn't exist.
Every API endpoint, every config option, every operational procedure.
